# 学生个人知识库

学生登录本地门户 http://127.0.0.1:8790/，进入课程，打开小鸭，点击“学习档案”。独立的 8793 课堂预览没有绑定学生身份，不读取个人档案。

## 档案内容

- 汇总已开放数学、英语、物理课程的知识点，按“未测、学习中、课程已达标、待巩固、达标后需复习”展示，支持学科及状态筛选。
- 保留概念评测反馈、核心问题、完整图谱诊断等证据。未测不等于薄弱，阅读、自述或未完成诊断不能证明掌握；历史达标与最近出现的问题分别保留。
- 汇总系统留存的数学错题、拍照题库作答次数、错误次数和最近结果。最近答对的题仍保留历史，但不继续作为“最近仍未答对”的提醒。
- 保存每位学生的课程总结、疑问与复盘，注明为学生记录，不直接改变评分、掌握度或奖励。每条最多 1200 字，每位学生最多 500 条。
- 自动生成学习概况和待巩固提醒。档案刷新保留未提交的总结草稿；同页切课时按课程区分草稿，退出页面前仍需点击保存。

档案基于已保存并同步到云端的证据，不代表系统了解学生全部能力。未留存的逐题答案、线下学习、历史对话不会补造。尚未同步或发生冲突时，会提示证据范围有限。

## 小鸭如何使用

每段开始讲课前读取当前学生档案，明确传递当前课程与知识点；文字提问时按问题检索跨课程知识点、错题和总结，再加入实时会话。切换知识点会清除旧上下文，并拒收上一知识点延迟返回的信息。语音转录完成后也会刷新检索，但实时模型可能在检索完成前开始回应，不能保证每次语音回答的第一句话已含最新记录。

会话中提供全科单元概况、最多 32 个相关知识点、12 道错题、8 条相关总结及当前课程的 2 条提醒；另提供最多 4 条明确关联当前知识点的错误证据 `mistakeFocus`。原始评测答案、手写笔迹与原图不加入档案上下文。小鸭应据此解释和温和提醒，每次聚焦一个待巩固点；不能将学生总结视为通过评测的证明。

## 讲到历史错题时

小鸭讲到相关概念或步骤时，应强调“这里你以前做题时出过错”，说明来源、题号或批改位置，再讲错因和避免方法，用简短问题确认理解。同一知识点不要求每段重复提醒。

- 错题库和试卷题目在同单元内按题面关键词关联知识点；仅同单元而无明确关键词的题目，不作为当前知识点的错误证据。关键词关联只能说明“这道相关题出过错”，不能证明当时错在该概念。
- 试卷/拍照题保留试卷名称、题号；普通错题库和独立手写作答不冒称考试。试卷归类理由不作为错因。
- 通过原稿结构校验、具有笔迹且无需复核的手写批改，可按知识点编号读取低于 80 分的反馈，作为有来源的历史错因。例如：“第1页第2步把中点当成垂足，中线不保证垂直。”这些反馈不直接改变课程掌握度。
- 只保存了对错而没有步骤或原因时，明确说“具体错因还没有记录”，请学生回忆当时步骤。一般易错点只能作为可能原因，不能编造成学生实际出错原因。
- 最近已答对或相关手写评阅已通过时，明确说明复习的是历史问题；原稿已修改但尚未评阅、或最新批改需复核时，只引用旧版本并说明当前情况未确认。

进入独立测验后，档案面板隐藏知识点、错题和总结，个人档案不再加入模型的教学指令。小鸭仍只允许澄清题意和通用规则。提醒目前出现在课堂内，不包含离线、系统后台或消息推送。

## 账号与存储

档案从现有 `GrowingDocuments` 和 `GrowingQuestionAttempts` 派生，不新增数据库表。总结使用独立文档键 `growing-student-notes-v1`，按学生 ID 保存，采用现有 revision 冲突检查。

- `GET /api/student/knowledge?unit=<课程ID>&topic=<知识点ID>&q=<问题>`：当前学生的档案与检索上下文，知识点必须属于指定课程。
- `POST /api/student/knowledge/notes`：提交 `{unitId,text}`，保存当前学生的总结。

身份来自服务端登录会话，不接受客户端选择学生 ID。未登录返回 401，家长和管理员不能调用学生接口读取其他人的个人档案。拍照错题同时检查试卷归属。门户在异步请求前后检查登录身份，换账号会销毁课堂，小鸭也会停止旧会话。

学习记录和相关总结会随教学指令发送给已配置的实时模型；模型不负责直接写回掌握度。实时音频和普通聊天仍不由本机语音代理自动存档。

## 维护与验证

核心代码为 `cloudflare/src/student-knowledge.ts`、`platform-web/app.js`，以及根项目 `app-design/course-duck.js`、`app-design/companion-duck/classroom.js`。知识点标题由 `scripts/export-english-rules.cjs` 从权威课程资产生成。

课程发布资产在 `app/src/main/assets/web/`。修改小鸭源文件后选择性同步到对应资产；不要把根项目的旧课程草稿全量覆盖到这里。

后端验证包括 TypeScript 编译、`cloudflare/test/student-knowledge.test.ts` 和 `cloudflare/test/api.test.ts`，涵盖知识点关联、试卷归属、错因来源、历史订正及学生隔离。根项目 `app-design/companion-duck/tests/check_student_knowledge.py` 覆盖真实本地登录与 D1 接口、总结草稿保留及持久化、切换学生、测验隐藏、手机布局及小鸭实际收到的指令，并检查切课后不继承旧错因、拒收旧知识点延迟消息；运行前需启动两个本地门户并安装 Playwright 和 Edge，脚本仅在本地开发库建立隔离测试账号。结果与截图在根项目 `.nmai/tmp/student-knowledge-check/`。实时模型使用本地 WebRTC 模拟，不代表真实服务商的个性化回答质量已验收。

本轮为本地实现，尚未发布线上或构建 APK。

已用隔离的虚拟学生记录完成一次真实 Qwen 语音联调：小鸭明确提到“手写作答批改记录”和“之前把中点当成了垂足”，解释中线不保证垂直，给出检查方法并追问能否分清中点和垂足。连接无报错，结束后麦克风音轨已释放，结果保存在根项目 `.nmai/tmp/duck-mistake-live/result.json`。这是单个示例的联调结果，不能代替所有学科和错题的教学质量评估。
