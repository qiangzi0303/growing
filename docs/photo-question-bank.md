# 拍照题库

拍照题库包含入口修复和“整页逐题批改 → 错因追问 → 知识点/模型复习 → 返回当前题目”，并将错题接入个人学习档案和小鸭。生产发布需先应用下文的 `0011_photo_review.sql`，APK 用户需覆盖安装对应新版。

## 入口与操作

网页登录后可从顶部或课堂进入“拍照题库”。APK 课堂使用原生入口打开云端题库，再返回来源课堂；不会再因缺少网页顶层 `GrowingCloud` 对象而点击无反应。独立课程预览没有登录环境时显示进入学习中心的提示。

学生使用自己的题库；家长需先绑定孩子并选择孩子；管理员可搜索学生。

1. 拍一页，或从相册选择照片，按页序添加。每批最多 4 页、40 题。
2. 默认选择“整页逐题批改”，直接分析题干、图形和学生实际作答，保存原图与逐题批改。也可选择“只识别题目入库”，只转录文字、不保存新照片、不产生首次评分。
3. 批改成功后进入逐题工作台：左侧看原始作业和本题定位框，右侧切题、核对识别内容、查看得分与逐步错因。定位不可靠时不画框，提示结合整页核对。
4. 可问“这一步为什么错”“只提示下一步”“换一种讲法”，也可自由追问。追问围绕所选批改记录展开，不重新评分。
5. 从“错误反映的薄弱点”“本题考查的知识点”或“几何模型匹配”进入真实课程复习。模型入口附适用条件说明。点击固定“返回当前题目”或课程自身返回按钮，回到当前题目和批改。
6. 填写完整订正过程后单独批改。首次原稿评分与每次订正分别保存，可切换历史；题干修改后，旧批改标记为旧版本，需提交新作答后再追问。

每题按 100 分制评估本次表现，不推断原试卷总分和每题配分。未作答、关键条件缺失或无法可靠判分的题分别标为“未作答”“待人工核对”，分数为空，不计对错。可靠的首次批改和订正各记录一次作答；重复请求不重复计次，不改动原课程掌握进度或奖励。每题最多保存 20 次批改、30 次追问；失败保留输入供重试。

## 学习档案与小鸭

拍照错题自动出现在当前学生的学习档案，包含来源试卷、题号、错误次数、最近状态，以及可展开的历史评分、错误位置、错因、订正建议和关联知识点。直接读取题库已保存的批改，退出后重新登录仍可读取；不另造一份可漂移的评分记录。

小鸭会接收与当前课程或提问相关的错题摘要，并区分“仍需订正”“最近答对，保留历史错误”“题干已变更或最新批改待核对”。只有批改明确指出的知识点错误才作为薄弱证据；仅仅考查了该知识点不能认定学生不会。课程已达标时显示需要复习，保留原达标记录和奖励。旧题只有对错次数时，小鸭说明缺少错因，不自行编造。

批改、订正、自查和题干修改保存后，网页登录课堂会刷新已打开的档案和语音上下文。APK 本地课堂按当前已绑定的学生云账号读取同一档案；需要联网，尚未正常同步的本地课程草稿不包含在云端结论中。切换账号会核对身份，不能读取其他学生档案。

发给小鸭的是保存评分与错因的文字摘要，不包含原图、完整学生作答或参考答案。小鸭不能声称看过原图，拍照文本中的命令也不能更改教学规则。最近订正通过后仍可复习旧错因，但不能继续说这次订正错误，也不据此认定整个知识点已经掌握。

## 真实课程关联

单元目录来自已打包课程，覆盖八年级数学上下册、英语上册、物理上册，共 24 个单元。不确定或目录外题目归入“待归类”，低于 0.8 的置信度不自动指定单元。

`scripts/build-photo-learning-catalog.cjs` 从 APK 实际使用的 `handwriting-core.js`、`math-data.js` 和三个 `geometry-models-*` 数据脚本生成 `cloudflare/src/photo-learning-catalog.json`，包含 140 个知识点、41 个几何模型。目录提供课程标准、适用条件和证明方法，链接由服务端生成并检查目标页存在，AI 只返回候选 ID 和本题证据。

题目考点与学生薄弱点分开。只有原稿中可确认的错误才能标为薄弱点；模型匹配需核对实际题设和图形条件。置信度低于 0.8 不显示跳转，没有可靠匹配时不强配。AI 结果仍需结合原稿核对。

## 题面与照片保存

题干、选项、小问、图示条件与参考答案仍保存为可编辑文字和标准数学公式；学生作答单独保存，不混入参考答案。缺图、模糊内容保留明确疑点，不补写学生过程或标准答案。题库支持单元筛选、编辑与已核对标记。

照片在设备上转为 JPG，每页最长边不超过 2000 像素，编码后不超过 500,000 字符。整页批改模式在同一 D1 事务内保存原图、题目、首次评分与有效作答；只识别模式仅保存文字与来源元数据。失败不留下半份试卷。上传成功后设备预览清空，整页批改原图可从已授权的题库重新读取。

每位学生最多 100 份试卷。同一学生、同一处理模式下，相同的一组处理后照片不重复入库；两种处理模式分别去重。不同裁剪、压缩或页序不视为相同照片。题干编辑检查版本号，AI 响应写入前再次核对授权和版本；撤销家长绑定后不能继续写入结果。

标准格式为 `math-text-v1`，行内公式使用 `\(…\)`，独立公式使用 `\[…\]`。服务端解析并验证题目、反馈和公式，拒绝图片题面、HTML/链接命令。学生直接输入的作答作为文本保留，展示时安全转义。KaTeX、字体和许可随网站及 APK 打包，不依赖 CDN。

旧题仍可逐题转换，保留 ID、归类、核对状态和错误次数；失败显示重试入口，原记录不变。已有历史来源页保留；无原图的文字题可在工作台提交文字作答。历史 `1025141010.pdf` 的 53 条文字转录保持原状。

照片发送至服务端 `HANDWRITING_VISION_MODELS` 配置的视觉服务，密钥仅在服务器使用。所有题目、原图、评分、追问均按学生授权，照片响应禁止缓存。草稿保存在当前浏览器会话、按学生和题目隔离；切换学生销毁旧工作台及其图片缓存。提示要求忽略照片中的姓名、学校、考号等信息。

## 接口与迁移

- `POST /api/question-bank/import`：增加 `mode=grade|transcribe`；旧客户端不传 mode 时兼容为 transcribe。
- `GET /api/question-bank/papers/:id`：返回原图（如有）及整份试卷题目。
- `GET /api/question-bank/questions/:id/review`：读取逐题评分与追问。
- `POST /api/question-bank/questions/:id/followup`：按所选 gradeId 追问。
- `POST /api/question-bank/questions/:id/correct`：按题干 revision 提交新的文字作答。

在已有 `0007_photo_question_bank.sql`、`0010_math_question_format.sql` 基础上，发布时还需应用 `0011_photo_review.sql`，增加处理模式、定位区域、批改与追问表。历史题默认 transcribe，不回填虚构评分。

复用既有视觉配置和限流。未配置、超时、无效 JSON 或不完整批改均明确报错，不计分。`sync-platform.py` 同步网页到 APK，`build-worker-assets.py` 构建 Worker 资源，二者均更新真实关联目录。不要运行全量课程同步覆盖已有课程更新。

Android 继续使用系统相机/相册与限定缓存目录的 FileProvider；本次无需新增相机或麦克风权限。网页上线后 APK 仍需更新以获得入口修复。

## 验证方式

- `cloudflare/test/photo-review.test.ts`：真实临时 D1，验证事务、幂等、授权隔离、绑定撤销、题干版本、追问不改分和订正历史。
- `scripts/test-photo-review.py`：隔离本地服务上的真实浏览器操作，覆盖整页工作台、手机布局、知识点和模型跳转、网页嵌套课堂返回、APK bridge 入口、失败重试及只识别旧流程。批改内容使用固定样例。
- `scripts/test-photo-review-live.py`：本地临时学生与合成作业，使用实际配置的视觉服务，验证分式错误、正确 AAS 证明、关联、追问及订正。不得以此替代多学科真实学生作业验收。
- `scripts/test-photo-knowledge.py`：浏览器执行真实导入、订正和档案读取，检查小鸭实际发送的语音会话指令、自动刷新、手机布局、APK 课堂适配和学生隔离。视觉结果与语音服务为固定模拟，不等于真实模型语音回答验收。
- `scripts/native-knowledge.test.cjs`：执行 APK bootstrap，验证学生绑定、认证请求、请求中切换账号及返回身份核对。
- TypeScript、已有 API 与网页回归、Worker 构建、Android 调试构建及 Lint；验证结果见本轮验收报告。

尚未在实体手机上验收系统相机拍摄，也未完成大规模、多学科照片批改质量评估；本地验收通过不代表生产已上线。
