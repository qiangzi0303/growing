# 登录身份确认

网站与 APK 云同步中心使用相同的云账号身份。登录及恢复已有会话时，以后台返回的 `roleSelectionRequired` 为准；未确认的普通账号必须选择“学生”或“家长”，保存成功后才能进入业务页面。管理员无需确认。

## 历史账号

旧版注册默认选中学生，数据库只有 `Role`，没有记录用户是否主动确认过。迁移 `0005_role_confirmation.sql` 添加 `RoleConfirmed`，已有普通账号默认未确认，因此上线后需要确认一次。原账号 ID、密码、会话、学习记录和家庭绑定均保留，不重新注册、不清空学习数据。

新版注册使用空的身份选项，必须主动选择；注册成功时将 `Role` 和 `RoleConfirmed=1` 一起写入数据库。

## 后台接口

- 登录和 `GET /api/auth/me` 返回 `role` 与 `roleSelectionRequired`。
- `POST /api/auth/role` 接收 `{ "role": "Student" }` 或 `{ "role": "Parent" }`，只更新当前登录账号，不接受其他用户 ID，也不能设置管理员。
- 角色和确认标记原子写入；重复保存相同身份可重试，已确认后保存不同身份返回 409，避免不同设备覆盖选择。
- 未确认账号可以查询自身资料、选择身份或退出，其余需要登录的业务请求返回 403。公开首页和下载仍可使用。
- 失败时保留选择页面并提示重试；后台保存成功后，刷新、下次登录及其他设备登录都读取已保存的身份。

## APK 云账号与本机账号

学生云账号仅在身份确认后关联本机记录，并继续校验已有学生绑定，防止换成其他学生后串档。家长可在云同步中心进入家长看板，不关联或上传当前本机学生的学习记录。

APK 原有离线用户名/密码属于独立本机账号，本次未修改其登录和存储模型。浏览器验收模拟 Android JS 桥接；实体 Android 设备尚未验证。

## 发布

使用项目现有“一键提交发布.bat”，先应用新增 D1 迁移，再部署 Worker 和共享页面，随后构建 APK。旧 APK 云页面可能无法显示新的确认步骤，用户可先在网站登录确认身份，或更新 APK。未确认前，后台会拒绝其业务同步请求。
