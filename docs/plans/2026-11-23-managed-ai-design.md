## 建议采用的方案

管理员在现有管理后台配置模型，网站、APK、小鸭和各课堂使用已登录的云账号调用后台。模型供应商的长期 Key 只在后台使用，不返回前端。后台从供应商响应获取用量并按认证账号记录。

比较：下发 Key 给前端虽改动较少，但无法可靠统计绕过后台的调用，也会暴露共享密钥；只把文本代理到后台会漏掉图片识别、批改与实时语音。建议统一覆盖文本、视觉和语音三条链路。

当前请求视为功能实施请求；本方案不包含提交、部署或发布 APK。前面视觉预览稿与此次功能改造独立。

## 管理后台

新增“AI 模型”和“AI 用量”两个管理入口，沿用现有 Vue/Naive UI 组件和管理员权限。

模型配置包含：配置名称、供应商、用途（文本答疑、视觉批改、试卷识别、题图、实时语音）、模型 ID、HTTPS 接口、Key、启用状态与已支持的回退顺序。保留现有视觉模型必要的附加参数；音色可沿用设备偏好，个人 Key 和个人服务地址取消。

Key 写入后仅显示“已配置”及掩码，不提供回读完整值的接口。留空保存代表保留现有 Key；清除或替换使用明确动作。管理员连接测试也记入该管理员账户用量。

配置加密后存 D1，AES-GCM 的主密钥由 Workers Secret 提供；主密钥缺失时拒绝保存或解密，不退回明文。新增配置审计记录操作者、时间、配置 ID 与动作，不存 Key 或输入文本。普通账户无配置读写权限。

## 前端调用与迁移

- 前端仅读取模型名称、可用状态等公开元数据并请求后台，不接受或上传个人供应商 Key。
- 文本答疑、评分、复述、小鸭文本聊天走统一的已认证后台请求；现有视觉流程纳入同一配置与用量组件。
- 所有学生/家长端删除 Key、模型服务地址输入和保存/测试个人 Key 的入口；未配置显示“请联系管理员配置 AI 服务”。
- APK 使用现有云会话；未登录或离线时提示登录/联网，保留离线课程和历史记录。会话退出或换账号后旧请求取消或失效，不能写到新账号。
- 不自动收集客户端旧个人 Key。旧值不再被读取或使用，移除旧接口的返回能力；不为清理 Key 而清空学习数据。
- 现有服务器视觉/语音配置仅通过服务器侧受控迁移导入管理配置。迁移可重跑且不覆盖已编辑的新配置；完成切换后避免两套来源长期并存。

## 用量口径

主账记“发起调用的已认证云账户”。家长为孩子录入或批改时，同时保留操作者账户与受益学生字段，默认合计只计一次。管理员测试归管理员本人。

每次真实上游尝试独立记录：内部调用 ID、请求关联 ID、账号 ID、关联学生（若有）、功能、模型配置版本/模型 ID、供应商请求 ID、开始/结束时间、状态、输入/输出/总 Token，以及供应商提供的缓存、推理或音频明细。实际字段以供应商返回为准；细分数值可能包含在总量里，不能重复加总。

一次业务调用触发多个模型或重试时，各次真实消耗分别计入；幂等键防止同一供应商响应重复入账，不把真实第二次调用错误去重。供应商返回用量但业务内容无效或校验失败时，仍记录已经发生的用量。

供应商未返回 usage、请求超时或断开且无法确认用量，显示“用量未知/待核对”，不可记为已确认 0。保存开始记录，防止中断造成整条调用消失；统计展示已确认合计与未知调用数。旧版本直连的历史用量无法可靠补算，统计从新链路启用时开始。

用量页面：按日期、账户、模型、功能筛选；显示输入/输出/总 Token、请求数、失败数和未知用量数，可展开调用明细。日期按北京时间展示，数据库存 UTC，使用明确的时间区间边界。暂不加价格估算、充值或配额限制。

## 实时语音需要专门迁移

现有 WebRTC 的 response.done 由前端接收，仅由前端回传 Token 不能作为可信账本。目标是采用后台可观察供应商事件的实时连接：优先核实当前 Qwen 模型是否提供可用的服务端事件连接或官方会话用量查询；若不能在现有 WebRTC 连接上取得可信事件，则改为后台 WebSocket 中继，前端负责音频采集/播放。

实施前核实官方协议、音频格式、打断/取消和鉴权要求，不猜测接口。语音最终验收必须覆盖上游实际 usage 事件，不能以客户端估算代替。若当前供应商协议无法提供所需用量，明确报告限制，不声称全量统计已完成。

## 安全与失败行为

沿用现有登录、角色权限、X-Growing-Client、请求大小限制与频率限制。普通客户端不能指定上游 URL、Key、记账账号或任意未启用模型；配置地址不接受内网/回环目标或重定向绕过。自定义请求头作为秘密配置处理，不能覆盖后台鉴权策略。

后台错误只返回稳定错误码和可操作提示，不透传供应商带凭据的原始错误。日志/审计/用量表不保存提示词、图片、原始音频或 Key。配置版本随调用记录，避免管理员修改配置导致历史模型归属变化。

## 实施顺序和验收

1. 配置、加密与用量迁移：权限、掩码响应、主密钥缺失、幂等迁移和并发入账测试。
2. 文本/视觉代理：认证账号归属、绕过/伪造拦截、供应商 usage、无 usage、内容无效、回退多次、取消与重试测试。
3. 后台两页：配置保存/留空保留/替换、管理员连接测试、日期/账号/模型筛选、空态和权限拒绝；真实组件行为测试、类型检查与生产构建。
4. 全部客户端与资产同步：课程/小鸭调用适配、设置入口移除、原生接口停止返回 Key，旧成绩兼容、会话隔离及浏览器操作验证。
5. 实时语音：先验证官方协议，再实现可信计量链路，验证打断、播放、退出与断线后的记录完整性。
6. Workers 类型检查、针对性 API 测试及打包；Android 编译与针对性原生测试；生成资产检查。真实供应商连通与真机麦克风测试单独报告，不用 mock 通过替代。
