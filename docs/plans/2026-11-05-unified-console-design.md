# 逆流统一管理后台设计

日期：2026-11-05。状态：整体方案已由用户确认，进入实施计划阶段。

## 1. 已确认的目标

管理员后台和家长端合并为一套后台，采用 Soybean Admin。统一入口、登录及页面组件，按身份显示菜单，并由服务端限制数据范围。

用户已选择：

- 家长手机端简化菜单，突出孩子概况、孩子切换和待确认奖励。
- 首版完整迁移现有功能，不同时新增课程、单元、试卷、错题的集中内容管理系统。
- 保留学生课堂，先在本地完成迁移和验证，再单独安排上线。

## 2. 技术架构

新前端源码放在 `growing/console-web/`，构建资源由现有 Worker 同域名提供，入口为 `/console/`。复用 Cloudflare Worker、D1、现有用户及会话，不建立第二套账号数据库。

模板来源：<https://github.com/soybeanjs/soybean-admin>。

调研时固定的上游提交：`d2dfefd757e37d8d6077ea1cea6181fb628d6097`，其 package.json 为 2.3.0，采用 Vue 3、TypeScript、Naive UI、Pinia、Vue Router、Vite Plus、UnoCSS。采用完整工作区及其内部 packages，保留 MIT 许可证和来源说明，不只复制 src 后猜测依赖。

该版本 packageManager 指定 `pnpm@12.10.1`，engines 声明 Node >=20.19.0。实施时核对工具链实际兼容性，先完成最小构建；如果工具链存在阻碍，应明确说明并记录替换的固定上游版本。

使用 Vue Router 的 `/console/` history base。Worker 为明确的前端页面路由提供 `/console/index.html`，缺失资源和未知业务路径返回 404，不把 API、学习资源或任意带文件扩展名的地址回退到 HTML。

构建输出仅进入 `growing/cloudflare/public/console/`；不把后台工作区整包复制进 APK。现有 `build-worker-assets.py` 会清理未登记文件，因此必须将后台输出纳入同一份资源登记流程。

## 3. 登录和权限

沿用 `/api/auth/login`、`/api/auth/me`、`/api/auth/logout`，以同源 HttpOnly Cookie 维持网页会话。所有写请求保留 `X-Growing-Client: 1`。

Soybean 默认接口使用 userName、业务响应包裹、token/refreshToken，与当前 username、原始 JSON 和 HTTP 状态约定不一致。替换模板的认证请求、恢复会话及路由守卫，不新增不存在的刷新接口，不将网页登录返回的 token 写入 LocalStorage。

- Admin：后台首页可读取全站概况，可访问全站学生与会员管理。
- Parent：进入孩子概况，只能读取已绑定孩子的数据。
- Student：返回现有学生入口，不能进入管理功能。
- 待确认身份账号：先完成现有身份确认流程，再分流。
- 未登录：进入登录页，登录后只恢复本站后台内允许的目标地址。

菜单隐藏仅用于界面呈现；实际请求继续由现有 Worker 验证身份、亲子关系、操作范围。不能为了后台预览而放开 `/learn/` 给家长。

401 清空当前页面缓存、撤销请求并要求重新登录；403 显示无权访问，不能作为空数据展示。跨页、切换孩子、退出及切换账号时，用 AbortController 和请求序号避免迟到响应写入新页面。

## 4. 页面结构

| 路由（相对 /console/） | 页面 | 范围 |
| --- | --- | --- |
| home | 工作台 / 孩子概况 | 按身份提供不同内容 |
| students | 学生档案 / 我的孩子 | 管理员搜索、分页；家长仅绑定列表 |
| students/:id | 学生详情 | 共用页面，服务端判断数据权限 |
| reports | 学生学习报告 | 学生选择、学科及册次筛选 |
| members | 注册会员 | 管理员，搜索、身份筛选、分页 |
| members/:id | 会员详情 | 管理员，账号及亲子关系操作 |
| rewards | 奖励记录 | 管理员全站账本；家长按孩子查看与确认 |
| account | 账号与设置 | 当前账号、家长添加孩子、连接设置入口、音效及退出 |

旧拍照题库和管理员课堂试用作为兼容入口保留。它们不强行嵌入一份失去上下文的旧 HTML，也不让学生课堂加载整个后台依赖。

### 4.1 工作台

管理员展示已有统计：注册会员、各身份人数、已有同步活跃统计和奖励确认账本汇总。首版不虚构待办、趋势或告警数据。

家长展示当前孩子的学习概况和未确认奖励，多孩子可切换，无孩子时显示添加入口。汇总取自现有报告；暂缺字段显示未知或暂无记录，不用零填补。

### 4.2 学生详情

共用详情包括：

1. 数学、英语、物理概况及今日、累计有效学习时长。
2. 成长曲线，保留 7/30/90 天、学科及指标筛选；缺少快照的日期保持空值。
3. 单元学习报告，保留现有课程达标、评测和时间口径。
4. 排名、反复错题及最近作答记录。
5. 现有手写原稿、照片作答及批改历史的查看入口。
6. 设备奖励记录和独立的家长云端确认账本。

不把手写评分等同课程达标，不把设备累计核销摘要与确认账本相加。学习报告列表只加载摘要，原稿和大图片按需获取。

照片答案历史以已有接口实际提供的数据为准：先核对存储和读取链路，已有能力完整迁移；若统一后台缺少读取原稿所需接口，只补充受同等权限保护的只读接口，并增加权限及历史完整性测试。不得因为列表只有统计字段而宣称历史已迁移。

### 4.3 会员与家庭关系

保留会员搜索、分页、详情、按会员筛选账本、修改密码、修改 Student/Parent 账号类型、搜索学生添加亲子绑定及解绑。

保留原有操作语义：修改密码使该用户会话失效；修改身份解除原绑定并使旧绑定码失效；学习记录和历史账本保留。管理员不能从此页面把普通账号提升为管理员。

家长添加孩子继续支持现有账号密码验证流程，不存储孩子的明文密码。家长自助解绑当前没有对应页面和接口，不借迁移新增该业务；现有管理员解绑能力完整保留。

### 4.4 奖励

管理员可以查看全站及指定会员账本；家长只能确认已绑定孩子的实际兑现记录。确认前明确列出孩子、奖励及金额/分钟；重复提交不产生重复账本。管理员不冒充家长确认，云端确认也不实际转账或再次扣除奖励。

### 4.5 兼容入口和本机设置

拍照题库继续使用现有账号、孩子选择、导入、试卷及批改流程；管理员课堂试用继续使用隔离的本机试用空间，不写入任何学生档案。

DeepSeek 和语音连接设置保留当前按账号隔离的本机存储语义。后台只复用既有设置能力，不把本机密钥同步到数据库、写进 URL 或日志。保留音效开关及退出。

## 5. 手机和桌面布局

桌面沿用模板侧栏、顶部账号菜单、面包屑及内容区，显示真实业务菜单。家长手机端收起侧栏，在首页优先显示孩子切换、概况、报告及待确认奖励。

会员等宽表格在窄屏采用摘要卡片或表格内部滚动，页面本身不能横向溢出。表单控件带标签，错误紧贴操作，确认窗口能用键盘完成。保留逆流品牌；主题先采用模板基础浅色主题并统一品牌色，不额外开展全站视觉重设计。

## 6. 数据与接口复用

| 能力 | 当前接口 |
| --- | --- |
| 登录及身份 | `/api/auth/login`、`/api/auth/me`、`/api/auth/role`、`/api/auth/logout` |
| 全站概况 | `/api/admin/overview` |
| 会员及管理操作 | `/api/admin/members`、`/api/admin/members/:id` 及 password、role、children 子路径 |
| 家长孩子列表、添加 | `/api/parent/children`、`/api/parent/children/account` |
| 管理员学生报告 | `/api/admin/students/:id/report?days=30`，返回报告、曲线及奖励组合 |
| 家长学生报告 | `/api/parent/children/:id/report`、growth、rewards 子路径 |
| 单元、排名、原稿 | 对应管理员 students 或家长 children 下的 unit-report、rankings、handwriting |
| 反复错题及记录 | `/api/question-bank/repeated`、`/api/question-bank/attempts`，明确 studentId |
| 全站确认账本 | `/api/admin/redemptions` |
| 家长确认奖励 | `/api/parent/children/:id/confirm-redemption` |

请求层统一适配两种学生报告返回形状。所有数据缓存按当前账号、学生编号和筛选条件区分，换账号即清理。首版不改动已有学习文档格式，不计划批量搬迁数据；发现接口缺口后，只添加完成迁移所必需的能力。

## 7. 迁移和回退

1. 固定模板版本，完成本地工具链、构建和 Worker 资源接入。
2. 接入 Cookie 会话与角色路由，用本地测试账号验证。
3. 迁移管理员、家长和共用详情，逐项完成旧功能对照。
4. 保留旧入口作为回退路径；现有网页登录后按身份进入新后台，旧功能兼容链接显式绕开分流以避免循环。
5. 网页登录过期、浏览器刷新、旧书签及退出均需端到端验证。
6. Android 原生桥接和旧 APK 页面不自动跳到新后台；其现有行为需回归。本次不包含 APK 发版。
7. 本地验收后单独安排部署。迁移不要求重建 D1、清空记录、修改生产角色或自动提交现有未提交代码。

## 8. 错误与空状态

- 无孩子：显示添加孩子；无报告：显示暂无记录及刷新入口。
- 网络失败：保留可解释的错误及重试入口，不把失败当成零或空列表。
- 账号类型或亲子关系在操作中发生变化：展示后端冲突信息，刷新对应详情。
- 切换孩子后立即清除前一个孩子的可见数据，迟到响应不能覆盖当前孩子。
- 写操作禁用重复提交；失败后可重试，服务端幂等性继续生效。
- 显示文本及 AI 输出按不可信内容处理，不直接 v-html 插入原始内容。

## 9. 验收

先为认证适配、角色导航、报告归一化和切换竞态写失败测试，再实现。为 Worker 的资源回退和权限缺口增加有实际行为的测试。执行 TypeScript 检查、前端构建、已有后端测试及浏览器验证。

浏览器覆盖管理员、绑定两个孩子的家长、无孩子家长、学生和未登录者；覆盖 1280、768、390、320 像素宽度。关键验收为功能对照无遗漏、无越权、无账号/孩子串数据、历史记录完整、会话恢复和旧入口正常。

测试数据仅在本地数据库或隔离测试夹具中创建，不调用真实 AI，不操作生产账号或确认真实奖励。文档完成不代表实现和验收已完成。
