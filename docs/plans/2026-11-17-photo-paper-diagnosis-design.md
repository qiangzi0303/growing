# 拍照试卷错题、知识图谱诊断与单元红点

日期：2026-11-17。2026-11-18 用户追加实施要求：拍照试卷和 AI 批改等使用本地缓存；按共享记录方案一并推进。红点采用推荐的待订正规则，保留历史。

## 用户目标

拍照试卷处理后，错误题目自动出现在对应单元错题中；依据实际错题形成知识图谱诊断；单元仍有错题时，目录中显示红点。网页和 APK 使用一致规则，保留原卷、作答与批改历史。

## 已核实的现状

- `platform-web/student-paper-pages.js` 的试卷上传入口没有传 `mode: grade`；拍照批改入口才传。整理题面不等于已经判断学生作答正误。
- `cloudflare/src/paper-import-jobs.ts` 已具备逐题视觉处理与批改阶段，批改模式通过 `photoGradeStatements` 保存批改和有效作答记录。
- `cloudflare/src/paper-ai.ts` 的原卷批改仅返回结果供面板展示，没有保存正式批改记录。
- `cloudflare/src/question-bank.ts` 的单元题库排除了 `paper-draft`，错误筛选使用存在历史错误的规则；试卷图谱则读取当前题面版本的最新批改。两处口径不同。
- `app/src/main/assets/web/app-design/student-math-resources.js` 的单元错题内容主要来自固定归档；个人拍照题库另有入口。
- 现有 `paperGraph` 仅支持数学，主要列出单元、知识点与题目，尚未构成完整的错因诊断。知识目录实际包含数学 68、物理 40、英语 32 个节点。
- `student-catalog-model.js` 和 `StudentCatalog.vue` 没有学生错题状态及红点。已有 `growing:knowledge-changed` 事件可用于刷新。

## 方案比较

1. **推荐：共享题目与批改记录，统一查询规则。** 原试卷题保留唯一 ID；单元错题、图谱和目录都引用它。订正、调整单元后各入口保持一致，无需复制照片与历史。
2. **备选：批改后复制到独立错题库。** 初期容易接入，但会产生两份题目及成绩，需要额外同步订正、删除、归类变更，不推荐。

## 处理与归档

- 新拍照试卷默认执行“整理并批改”，沿用现有可恢复任务。空白题标记未作答，不制造错误；只有错误或部分正确的有效判断进入个人错题。
- 识别、题图或批改失败的题保留原稿和任务进度，明确待处理，不显示为已经诊断完成。
- 复用批改持久化入口，原卷批改面板成功后也保存正式结果；使用请求 ID 保证重试不重复计分。独立 AI 解答仍只提供讲解，不产生学生成绩。
- 依据可靠的题目单元和已验证知识点归类。跨单元题可在多个相关单元中被引用，整卷统计按唯一题目 ID 去重。
- 不确定归类的题进入“待归类”，核对后出现在对应单元。不能按题号或整张试卷所属单元强行分配。
- 单元错题入口展示个人拍照错题并沿用原稿、订正、批改记录。固定教学归档保留，但不能仅因收录就算作该学生做错。
- 已保存的有效批改通过统一查询自动纳入；旧的仅整理试卷提供继续批改入口，不默默批量调用模型或改写生产历史。

## 错题状态与红点（规则待用户选择）

建议红点表示“仍有未解决的错题”，默认设计如下：

- 当前题面版本的有效结果为错误或部分正确：进入待订正，点亮关联单元。
- 后续有效订正批改正确：保留历史错题，解除本题待订正状态；单元其他错题未解决时红点继续显示。
- 仅打开题目、查看答案、查看诊断，不消除红点。
- 曾经做错、最近一次批改失败或待复核：不能据此消除已有提醒；展示待复核状态。题面改版后的旧批改保留为历史，不据旧版结论新增错题。
- 从未得到可靠错误判断的空白题、模糊题、失败题，不作为新错题点亮红点。
- 红点同时覆盖该学生已有的有效单元错题，不只统计本次上传试卷。历史教学样例不纳入个人提醒。
- 目录批量读取单元摘要，不为每个单元分别发请求。刷新、切换学生、重新进入页面与批改完成后更新；读取失败不伪报“零错题”。
- 单元标题旁显示小红点，提供“本单元有待订正错题”的可访问文字；点击相关入口到本单元错题，不增加繁杂提示。

如果用户选择“只要存在历史错题就显示”，改用历史错误去重计数；订正正确后红点仍保留。两种口径不能混用。

## 知识图谱诊断

- 数学、英语、物理使用各自现有真实知识目录与课程链接；只展示有证据的关联。
- 同时提供单份试卷与学生累计错题范围，以单元、知识点和来源题目组织。
- 明确区分 `tested`（题目考查）和 `gap`（批改指出的薄弱点）；不能因为一道综合题做错，就把全部考查知识点标为薄弱。
- 节点展示待订正题数、重复出错情况、具体错因与来源证据；可以回到原题、实际作答和相应课程。
- 最新订正正确后保留历史诊断与改善记录，不再把该题当作当前未解决证据。一次正确不代表整个知识点已掌握。
- 批改没有可靠知识点结论时，允许只有单元关联或待核对状态，不编造知识点。
- 从有效记录计算诊断，不为每次打开图谱额外调用模型；不改写原有课程掌握度、评测成绩或奖励。

## 数据与权限

以 `studentId + questionId + questionRevision` 关联有效记录，跨试卷相同题号互不混淆。复用现有题目、批改、作答表；只有经实现验证确有必要时才添加迁移。

服务端统一校验学生身份、家长实时关联及管理员权限。学生切换后旧请求不能写入新视图；解除家长关联后访问立即失效。原卷照片不放进目录摘要或图谱响应。

## 预计修改边界

- 后端：`paper-import-jobs.ts`、`paper-ai.ts`、`photo-review.ts`、`question-bank.ts`、`index.ts`，复用知识目录和批改结构。
- 上传与个人错题：`platform-web/student-paper-pages.js`、`StudentPaperPages.vue`、当前单元错题控制器及入口。
- 诊断：现有试卷图谱数据接口、对应控制器/组件；补齐三学科入口并复用课程链接。
- 目录：`student-catalog-model.js`、`student-pages.js`、`StudentCatalog.vue` 及账户桥接的事件刷新。
- 仅同步实际改动的网页、APK 内嵌副本和构建资源，不用旧目录整批覆盖。

## 验收与执行方式

设计确认后按 superpowers 使用原生子代理实施及规格、质量复核：先写失败测试，再实现，再运行针对性验证。用户未授权 Git 提交或发布，本阶段不自动执行。

1. 以数据库/API 测试覆盖：上传批改、部分正确、空白、待复核、归类不确定、跨单元去重、重复请求、题面版本变更、订正正确，以及学生/家长权限隔离。
2. 用同一题验证单元错题、图谱、红点三个入口一致；也覆盖旧错题、从试卷页单独批改与调整归类。
3. 验证未批改不能生成薄弱点，考查知识点不全被标弱；诊断能追溯对应题与批改。
4. 编译后端 TypeScript、构建 Vue；运行目录和试卷控制器测试，验证错误提示及切换学生时旧响应隔离。
5. 浏览器检查桌面及手机布局，完成上传处理（模拟模型）、单元错题、图谱、订正、红点变化全过程。模拟调用只验证程序流程；真实照片识别质量另用项目内样卷核对并单独报告。

## 本地缓存补充（2026-11-18）

- 试卷列表、详情与原图、错题、诊断和完成的 AI 结果使用 IndexedDB 缓存；以服务地址、当前访问账号、学生和资源版本隔离。
- 缓存命中且未过期时不重复下载试卷。写入、订正、改题、改归类、重新批改后使该学生关联查询失效；主动刷新绕过缓存。处理中任务不缓存。
- 学生身份仍从有效登录会话取得。家长/管理员读取个人缓存前，使用轻量授权检查，失去权限不能展示旧缓存。退出及账号切换使在途请求失效。
- 缓存写入失败、浏览器禁用 IndexedDB 或容量不足时，正常在线功能继续；不删除原稿、学生草稿或服务器记录。限定缓存容量与有效期，仅清理缓存数据。
- AI 结果按学生、题目、题面版本、操作种类及相关题图版本复用；新答案、新题面、重新生成必须产生新结果。失败、取消、超时不缓存为成功。
- 本地缓存不取代服务器持久记录，不把读取缓存当成重新批改或重复计分。
