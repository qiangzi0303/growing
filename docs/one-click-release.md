# 一键提交发布

在项目根目录 `D:\成长\初二英语` 双击 **一键提交发布.bat** 即可。窗口会保留执行结果，完成后按任意键关闭。

默认会把 `growing` 仓库内所有未忽略的改动一起提交，提交说明自动带本地时间。请先保存文件，发布期间不要继续修改源码。

## 自动执行的步骤

1. 核对 main 分支、GitHub 仓库、Cloudflare 账户、数据库与域名，检查已有凭据和 CI 签名配置。
2. 同步网站/APK 共享资源，检查内嵌凭据，运行客户端、手写、课程、语音、AI、TypeScript 与 Worker 测试，执行本地打包演练。
3. 自动提交、推送 main，并等待该提交对应的 Web CI；无触发记录时自动补触发。
4. 应用尚未执行的 D1 迁移，部署网站与 Worker，保留 `007yx.com` 和旧 workers.dev 地址。
5. 等待同一提交的 Android CI，由 CI 沿用现有签名、生成递增版本、执行覆盖升级与平板测试、上传 APK 和更新清单。
6. 将签名 APK 下载到 `apk\build-<构建号>`，校验包名、版本、固定证书指纹、SHA256 和完整内置资源，再校验两个域名的公开下载与健康接口。

任一步失败立即停止，并显示日志位置。已执行的迁移和部署不会回滚；脚本不会自动重置、强制推送或重新生成签名。

## 检查与可选参数

- 双击 **仅检查发布.bat**：运行本地检查和远端只读检查，不提交、不推送、不迁移、不部署、不触发 CI。
- 无网络时：`growing\release.bat --check --offline`，只验证本机。
- 自定义提交说明：`growing\release.bat --message "更新手写作答功能"`。
- CI 默认每个工作流最多等待 60 分钟；可用 `--wait-minutes 90` 调整。

检查模式会同步生成资源、生成本地打包输出和日志；不改变线上服务。源码改动尚未保存到 Git 时，检查也可以运行。

## 失败后继续

修复错误后重新双击一键文件即可。发布状态存放于 `.nmai\releases\state.json`，每次日志存放于 `.nmai\tmp\releases\时间戳`；不要随意删除状态文件。

- 推送成功而部署失败：再次运行会沿用当前提交对应的 CI 构建。
- CI 失败：本次停止；再次运行会重试 Web 任务，或为失败的 Android 构建触发一个新版本，避免覆盖已发布版本的安装包。若修改源码，则自动提交并产生新版本。
- CI 等待超时：再次运行继续等待当前提交。
- 同一提交已完整发布：重新校验已有 APK 与公开下载，不重复生成版本。
- 同时运行两个窗口：后启动的进程会停止，避免重复发布。

首次使用本机已有 Python、Node、Git、Git Credential Manager、Wrangler 登录和 `cloudflare\node_modules`。脚本会说明缺失项，不自动改账户或覆盖签名。依赖缺失时先在 `growing\cloudflare` 运行 `npm ci`。若 Python 路径变化，可通过环境变量 `GROWING_RELEASE_PYTHON` 指向实际的 `python.exe`。

密钥不写入批处理或仓库；GitHub 凭据来自系统凭据管理器或 `GH_TOKEN`/`GITHUB_TOKEN` 环境变量，签名与 APK 发布凭据继续由 GitHub Actions 管理。日志属于项目本地文件，请按项目内部资料保管。

脚本验证发布流程和包的一致性。真实图片 AI 评分效果、实体手写笔兼容性仍需使用实际设备单独验收。
